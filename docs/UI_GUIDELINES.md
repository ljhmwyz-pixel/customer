# UI 设计规范

版本 v1.0　　最后更新 2026-08-04

本文给出的数值可直接落进 `lib/theme/tokens.dart`，页面内不再硬编码。

## 1. 设计定位

这是一个高频作业工具，不是展示型产品。销售一天要打开几十次，每次停留可能只有十几秒。

因此设计目标是**可扫描、可比较、可快速操作**，而不是视觉惊喜。

具体表现为：信息密度偏高、留白克制、接近系统原生观感、状态用颜色和位置区分而非装饰。

### 明确避免的做法

这些是工具型应用最常见的业余化来源：

- 过大的标题区或 Banner，挤占本该显示数据的空间
- 把页面区块做成浮动卡片，卡片只用于列表中的重复项与弹窗
- 卡片里再套卡片
- 自创渐变背景、装饰性光斑
- 字号随屏幕宽度缩放
- 负字距
- 单一色系主导整个界面

## 2. 配色

### 主色种子

主色取自银灰虎斑猫的黄绿色眼睛，是一个中性偏冷的黄绿：

```dart
static const seedColor = Color(0xFF7A8B3F);
```

用 `ColorScheme.fromSeed` 推导出全部语义色槽，明暗两套：

```dart
ColorScheme.fromSeed(seedColor: seedColor, brightness: Brightness.light)
ColorScheme.fromSeed(seedColor: seedColor, brightness: Brightness.dark)
```

这样一个决定换来一整套自洽配色，包含主色、容器色、前景色、错误色及其暗色版本。

### 使用原则

主色只用在关键操作与关键状态上。大面积区域保持中性灰白，这样重要的东西才会真的跳出来。

全屏范围内主色的可见面积不超过 15%。

### 语义色

业务状态色不从主色推导，单独定义，因为「逾期是红的」这件事不能随主色变化。

但色相稳定不等于色值不变：同一个红在浅底和深底上的对比度差很多。所以每个语义
有明暗两个值，色相一致，明度按背景调整。

```dart
// 浅色主题
overdue   = Color(0xFFC62828)  // 逾期，红      5.34:1
today     = Color(0xFFBF360C)  // 今日待办，橙  5.33:1
upcoming  = Color(0xFF1565C0)  // 未来待办，蓝  5.46:1
done      = Color(0xFF2E7D32)  // 已完成，绿    4.87:1
inactive  = Color(0xFF616161)  // 已流失，灰    5.74:1

// 深色主题
overdueDark  = Color(0xFFFF8A80)   // 8.12:1
todayDark    = Color(0xFFFFB74D)   // 10.71:1
upcomingDark = Color(0xFF82B1FF)   // 8.55:1
doneDark     = Color(0xFF81C784)   // 9.21:1
inactiveDark = Color(0xFF9E9E9E)   // 6.92:1
```

后面的比值是与对应主题 `surface` 的对比度，全部达到 WCAG AA 对正常字号的
4.5:1 要求。语义色用在文字和 3px 竖条上，不能只满足大字号的 3:1。

两个值偏离了常见的 Material 调色：`today` 没用 `0xFFE65100`（只有 3.6:1），
`inactive` 没用 `0xFF757575`（4.38:1）。都是实测不达标后加深的。

**页面代码不直接引用这些常量**，统一走取色入口，否则深色下会拿到浅色值：

```dart
final semantic = AppSemanticColors.of(context);
Text('逾期', style: TextStyle(color: semantic.overdue));
```

`test/app_skeleton_test.dart` 里有对比度测试守着这条约束，改色值时会自动校验。

客户阶段色：

```dart
潜在客户  inactive
已接触    upcoming
意向明确  today
已成交    done
已流失    inactive（配合降低不透明度）
```

客户分级不用颜色区分，用字母标记 A / B / C，避免颜色语义过载。

### 对比度

正文文字与背景对比度不低于 4.5:1，大号文字不低于 3:1。暗色模式需单独验证，不能假设自动推导的结果一定达标。

## 3. 间距

统一使用 4 的倍数，只用这六档：

```dart
static const s4  = 4.0;   // 紧邻元素，如图标与文字
static const s8  = 8.0;   // 组内元素
static const s12 = 12.0;  // 卡片内部padding
static const s16 = 16.0;  // 页面左右边距，卡片间距
static const s24 = 24.0;  // 区块之间
static const s32 = 32.0;  // 页面顶部或大区块分隔
```

页面左右边距固定 16。列表项之间 8。区块标题与内容之间 12。

不出现 10、14、18、20 这类非 4 倍数值。

## 4. 圆角

```dart
static const r4  = 4.0;   // 标记、徽章
static const r8  = 8.0;   // 卡片、按钮、输入框
static const r12 = 12.0;  // 弹窗、底部抽屉
```

卡片圆角不超过 8。这是工具型应用保持规整感的关键，圆角一大就往消费类产品跑。

## 5. 字号

固定六档，不随视口缩放，字距一律为 0：

```dart
static const f24 = 24.0;  // 页面主标题，每页最多一处
static const f20 = 20.0;  // 区块标题
static const f16 = 16.0;  // 正文，客户名称
static const f14 = 14.0;  // 次要信息，跟进内容
static const f12 = 12.0;  // 辅助信息，时间戳
static const f10 = 10.0;  // 标记内文字
```

字重只用三档：`w400` 正文、`w500` 强调、`w600` 标题。不用 `w700` 以上。

**注意**：`f24` 只用于页面级标题。卡片、面板、侧栏、工具条内部的标题一律用 `f20` 或更小，不要把大字号带进紧凑容器。

## 6. 组件规范

### 客户列表项

高度固定，不因内容变化而抖动。每行显示四项信息：

```
[分级标记] 客户名称              [阶段标记]
           下次跟进：3天后 / 逾期2天
```

- 客户名称 `f16 w500`，单行超出省略
- 跟进时间 `f12`，逾期时用 `overdue` 色并加粗到 `w500`
- 阶段标记右对齐，`f10`，圆角 `r4`
- 整行可点击，点击区域高度不低于 48

逾期项在左侧加 3px 宽的 `overdue` 色竖条，这是最快能被扫到的视觉信号。

### 今日待办首页

首屏直接是待办列表，没有欢迎语、没有统计大卡片、没有 Banner。

顶部一行紧凑的计数：逾期 2　今日 5　本周 8。用 `f14`，逾期数字用 `overdue` 色。

分组顺序固定：逾期 → 今天 → 本周。空分组不显示标题。

### 跟进时间线

左侧 2px 竖线贯穿，每条记录一个 8px 圆点。圆点颜色按跟进方式区分（电话、微信、面谈）。

记录内容 `f14`，时间 `f12` 灰色右对齐。倒序排列。

### 表单

必填项只有客户名称，其余字段全部选填且默认折叠。展开入口写「更多信息」。

这是为了满足展会场景 30 秒录入的要求。一屏能看完的表单才可能被快速填完。

输入框用 `OutlineInputBorder`，圆角 `r8`，高度统一。

### 快捷时间选择

用 `ChoiceChip` 横向排列：明天 / 三天后 / 一周后 / 一个月后 / 自定义。

这五个选项覆盖绝大多数场景，避免每次都要开日期选择器。

### 按钮

工具类操作用图标按钮配 `Tooltip`，不用文字按钮。例如拨号用电话图标、附件用回形针图标、添加用加号。

只有明确的命令才用文字按钮，例如「保存」「删除」「导出」。

主操作用 `FilledButton`，次要操作用 `OutlinedButton`，第三级用 `TextButton`。一屏内 `FilledButton` 最多一个。

### 空状态

每个列表都要有空状态，包含一个图标、一句说明、一个引导操作。

说明文案描述当前状态而非解释功能，例如「还没有客户」配「添加第一个客户」按钮。

## 7. 布局约束

### 固定尺寸元素

列表项高度、标记宽度、图标按钮尺寸都要用明确约束定义，不能让内容长度改变布局。

悬停态、加载态、动态内容都不应引起位置偏移。

### 文字溢出

所有可能超长的文字都要处理：

- 客户名称、公司名　单行省略号
- 跟进内容　列表中最多两行省略，详情页完整显示
- 标记内文字　不允许换行，内容需在设计时限定字数

文字不得溢出容器，也不得遮挡相邻内容。

### 触摸目标

所有可点击元素的实际点击区域不小于 48x48，视觉尺寸可以更小。

## 8. 暗色模式

必须支持，跟随系统设置。

暗色下需单独检查三处：语义色在深底上的可读性、卡片与背景的层次区分、`inactive` 灰色是否过暗到看不见。

第一项已由语义色的明暗双值加对比度测试覆盖，见第 2 节。后两项仍需人眼在真机上看。

不用纯黑背景，用 `ColorScheme` 推导出的 `surface` 色，避免 OLED 屏上的边缘光晕。

## 9. 动效

克制使用。只在三处需要：

- 页面切换　用 go_router 默认过渡，不自定义
- 列表项删除　`AnimatedList` 的默认收起动画
- 状态切换　颜色过渡 150ms

不做入场动画、不做视差、不做弹性曲线。工具型应用的动效多了会显得慢。

## 10. 落地方式

全部数值定义在 `lib/theme/tokens.dart` 作为常量，`theme.dart` 组装成 `ThemeData`。

页面代码只引用 `AppTokens.s16`、`AppTokens.f14` 这类常量，不写字面量数字。

这样后期整体调整观感时只改一个文件，不用翻遍几十个页面找散落的数值。

## 11. 验收自查清单

每个页面完成后过一遍：

1. 页面左右边距是否为 16
2. 是否出现非 4 倍数的间距
3. 卡片圆角是否超过 8
4. 是否有卡片套卡片
5. 是否有字号随视口缩放
6. 字距是否为 0
7. 长文字是否会溢出容器
8. 可点击区域是否达到 48
9. 暗色模式下对比度是否达标
10. 主色可见面积是否超过 15%
11. 是否有空状态
12. 固定尺寸元素是否会因内容变化而抖动
