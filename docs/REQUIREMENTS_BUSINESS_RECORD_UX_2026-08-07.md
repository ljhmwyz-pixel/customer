# 本期需求：统一业务记录维护体验

日期：2026-08-07

## 背景

报价、样品、注册和招标记录虽然都能从客户详情进入维护，但附件与删除仍主要藏在客户详情的记录行中。用户进入编辑页后需要返回上一层才能继续处理附件或删除记录；注册和招标表单较长，保存按钮也容易离开视野。

## 目标

1. 四类已有业务记录在维护页直接显示当前记录上下文和状态。
2. 四类已有业务记录在维护页直接提供附件入口，并显示附件数量。
3. 四类已有业务记录在维护页直接提供删除入口，删除前二次确认。
4. 长表单的主要保存操作保持在屏幕底部可达。
5. 删除成功后刷新客户数据并回到客户详情；附件文件清理失败时明确告知会在下次启动重试。

## 交互规则

- 报价维护页显示报价编号、版本和当前收悉状态，保留“基于此报价新增版本”。
- 样品维护页显示样品型号和当前样品节点。
- 注册维护页显示国家/地区和当前注册状态。
- 招标维护页显示名称或项目编号和当前招标状态。
- “附件（N）”使用现有附件归属路由，返回后仍停留在当前维护页。
- “删除记录”使用显式文字和删除图标，不藏入更多菜单。
- 删除确认文案说明记录及其附件会被删除且无法撤销。
- 删除过程中禁用保存、附件和删除动作，避免重复提交。
- 新建样品、注册和招标时不显示附件与删除入口；保存后按现有行为返回客户详情。

## 不在本期

- 不修改数据库结构、状态枚举、提醒规则或任务同步规则。
- 不允许修改已有报价的编号、版本和金额。
- 不增加云同步、账号、审批或自动消息发送。
- 不调整订单维护页；订单已有独立的附件和删除操作。

## 验收标准

1. 报价、样品、注册和招标的编辑页均显示记录上下文、状态、附件数量和删除入口。
2. 四类附件入口均跳转到正确的 owner type 与 record id。
3. 取消删除不写数据库；确认删除后记录消失、客户数据刷新并返回客户详情。
4. 附件清理失败不阻断记录删除，页面提示下次启动自动重试。
5. 新建页不显示尚不可用的附件和删除动作。
6. 320px 宽度下操作区和表单无横向溢出，保存按钮保持可达。
7. 现有报价版本、样品节点、注册校验和招标风险确认规则保持通过。
