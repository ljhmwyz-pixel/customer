# 阶段 3 开发计划　客户管理闭环

创建于 2026-08-04　　依据 [PRD.md](../PRD.md) 第 5、8 节与
[UI_GUIDELINES.md](../UI_GUIDELINES.md)

## 1. 前置状态与目标

阶段 2A 的模拟器验收已完成，阶段 2B 仍为**待真机验收**。阶段 3 可先完成开发、
自动化测试和模拟器检查，但不得由此推导一加 13 / ColorOS 15 的提醒可靠性已通过。

本期把「录入客户 → 记录跟进 → 安排下次跟进 → 收到提醒 → 回到客户详情」做成完整
闭环，并补齐联系人、拨号、系统通讯录导入。客户名称是唯一必填项；快速录入不能被
次要字段阻塞。

## 2. 页面与路由

| 页面 | 路由 | 主要职责 |
|---|---|---|
| 今日 | `/` | 逾期、今天、本周三组待办；直达客户和新增客户 |
| 客户列表 | `/customers` | 紧急度排序、搜索、阶段与标签筛选 |
| 新建客户 | `/customers/new` | 名称快速保存，更多信息折叠，首条跟进可选 |
| 客户详情 | `/customers/:id` | 基本信息、联系人、计划、倒序跟进时间线 |
| 编辑客户 | `/customers/:id/edit` | 修改资料、阶段、分级和标签 |
| 新增跟进 | `/customers/:id/followups/new` | 记录跟进并强制选择下次计划或「暂不跟进」 |

通知深链继续使用 `/customers/:id`，`planId` 只作为可选 query 参数，不改变客户详情
的资源身份。无效 id 应显示可返回的缺失状态，不抛异常。

## 3. 文件与职责

- `lib/features/customers/customer_providers.dart`：查询条件、刷新信号、聚合读取与写入服务。
- `lib/features/customers/customer_widgets.dart`：固定高度客户行、时间文案和共享小组件。
- `lib/features/customers/customer_form_page.dart`：新建/编辑客户与标签。
- `lib/features/customers/customer_detail_page.dart`：详情、联系人、计划和时间线。
- `lib/features/customers/followup_form_page.dart`：跟进表单与下一计划约束。
- `lib/features/customers/contact_actions.dart`：拨号与系统通讯录读取的薄封装。
- `lib/features/home/home_page.dart`、`customers_page.dart`、`router.dart`：接入真实页面和路由。
- `test/features/`：业务服务、筛选、表单约束、深链、暗色和窄屏溢出测试。

不新增依赖；使用已锁定的 `flutter_contacts 2.3.1`、`url_launcher 6.3.2`、Riverpod、
go_router 和 Drift。列表默认沿用 `CustomerDao.listByUrgency` 的 SQL 排序；500 条规模下
筛选在一次结果集内完成，标签映射批量读取，避免逐行查询。

## 4. 交互与数据规则

1. 新建客户只填名称即可保存；名称去首尾空格后须为 1–50 字符。
2. 新建成功后可直接记录首条跟进，首页到「客户 + 首次跟进」不超过四次点击。
3. 客户列表行固定高度，显示分级、名称、最近待办和阶段；逾期行左侧显示 3px 红条。
4. 搜索覆盖客户名称、客户电话和联系人电话；阶段、标签可独立或组合筛选。
5. 保存跟进时必须二选一：创建下一计划，或明确勾选「暂不跟进」。
6. 跟进写入与客户 `lastFollowAt` 更新使用 DAO 事务；时间线按发生时间倒序。
7. 新计划先落库再调用 `ReminderScheduler.scheduleForPlan`。调度失败不回滚业务数据，
   页面显示警告，后续启动时由 `rescheduleAll()` 修复。
8. 拨号使用 `tel:` 并先检查系统处理能力；通讯录权限拒绝、无号码和取消选择都有提示。
9. 删除客户、联系人等破坏性操作必须二次确认；客户级联删除前先取消其未完成提醒。

## 5. UI 落地

页面水平边距 16px，控件触摸区域至少 48px。首页不放欢迎语和统计大卡；空分组隐藏。
客户行、阶段标记和图标按钮使用稳定尺寸，长名称与公司单行省略。跟进时间线使用 2px
竖线与 8px 圆点，内容完整显示。表单把可选资料收进「更多信息」，计划时间提供明天、
三天后、一周后、一个月后和自定义五个快捷选项。所有颜色来自 `ColorScheme` 与语义色，
暗色模式不使用硬编码浅色背景。

## 6. 实施顺序

1. 建立共享查询状态、刷新机制和业务写入服务，先用内存数据库覆盖核心规则。
2. 完成客户行、客户列表与首页分组，验证紧急度、组合筛选及 500 条数据表现。
3. 完成新建/编辑客户、详情和跟进表单，接通计划排期与通知深链。
4. 完成联系人增删、电话拨号和系统通讯录导入，并覆盖拒权与空数据状态。
5. 在窄屏、长文本、浅色和暗色主题下跑 widget 测试及模拟器人工检查。
