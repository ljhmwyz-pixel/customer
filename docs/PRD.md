# 外贸 CRM 跟进助手 SPRD

版本 v2.0　　最后更新 2026-08-05

需求来源：《外贸CRM跟进表开发需求文档_简洁版》V1.0，并结合现有 Android 客户跟进应用的技术基础整理。

## 1. 产品定位

一款面向医疗器械海外销售的单人本地 CRM。产品以“客户 + 项目”为业务主线，集中管理客户、联系人、产品机会、供应商替代、报价、样品、注册、招标、订单与复购，并把业务节点自动转化为每天可执行的跟进任务。

核心价值不是保存更多资料，而是持续回答四个问题：

1. 今天应该跟进谁？
2. 为什么现在要跟进？
3. 当前项目卡在哪里？
4. 下一步具体做什么？

应用继续采用 Flutter Android 本地应用作为主要交付形态，数据保存在本机 SQLite，不依赖网络、账号或云服务。Excel 作为完整业务数据的查阅与分析导出格式，不作为主数据源；Google Sheets 同步不在 v2.0 范围。

## 2. 目标用户与业务范围

### 2.1 使用对象

- 无锡宇寿医疗器械外贸销售人员
- 单人业务负责人
- 在同一设备上查阅业务进度的管理人员

v2.0 仍按单人单库设计，不增加多人协作、客户分配、角色权限和审批流。

### 2.2 适用产品

| 产品大类 | 产品与规格示例 |
|---|---|
| 一次性注射器 | 普通注射器、两件式、三件式、Luer Slip、Luer Lock、胰岛素注射器、AD 注射器、RUP 注射器、Safety Syringe |
| 高压注射器耗材 | CT、MRI、DSA；单筒/双筒套装；60–200 mL；300/600/1200 PSI |
| 连接管及配件 | I 型、Y 型、T 型连接管、Patient Line、Quick Fill Tube、Spike、Check Valve、12 小时/24 小时管路 |
| 设备及其他 | YSW6800、AZW5800、MX135 CT 球管 Insert、其他 OEM 医疗耗材 |

适配设备品牌包括 Bayer Medrad、Stellant、Mark V、Mark 7、Nemoto、A-25、A-60、120S、Liebel-Flarsheim、Optivantage、Optistar、Illumena、Medtron、Ulrich、ACIST、Antmed、Sino MDT 及其他品牌。

## 3. 设计原则

### 3.1 简洁

- 销售每天主要使用“今日任务”。
- 新增一次跟进时，核心更新项控制为：跟进日期、客户反馈、当前阶段、下一步行动、下次跟进日期。
- 非必要字段折叠展示，业务节点发生时再补充详细资料。
- 同一信息只录入一次，最近跟进结果和业务状态由系统同步与计算。

### 3.2 行动导向

- 每条任务必须说明客户、项目、跟进原因、下一步行动和负责人。
- 系统不使用空泛的“Any update?”作为默认建议。
- 报价、样品、招标、注册、订单与复购节点必须能形成具体任务。

### 3.3 可追溯

- 跟进记录只新增，不覆盖历史。
- 报价保留版本和结果。
- 样品寄送、签收、测试与结果保留完整节点。
- 项目阶段变化和关键业务动作保留时间记录。

### 3.4 本地可靠

- 飞行模式下核心功能可用。
- 任务提醒使用本地精确闹钟。
- 设备重启后重建未来提醒。
- 备份覆盖全部业务数据和附件。

## 4. 信息架构

最新表格需求中的四张核心工作表，在 App 中映射为四个核心业务工作区；Excel 导出时保持对应的四张工作表。

| 工作区 | 主要作用 | 使用频率 |
|---|---|---|
| 01 今日任务及看板 | 展示今日、逾期、报价停滞、样品停滞、近期复购、招标截止和关键统计 | 每天打开 |
| 02 客户及项目 | 管理客户资料、多个产品机会、现有供应商、替代策略和项目状态 | 需要时更新 |
| 03 跟进记录 | 每次联系新增沟通记录，保留完整历史并安排下一步 | 每次沟通后 |
| 04 业务追踪 | 统一管理报价、样品、注册、招标、订单与复购节点 | 发生业务节点时 |

“我的”页面属于系统设置，不计入四个业务工作区，用于权限、提醒自检、备份恢复、导出和使用说明。

## 5. 核心数据模型

### 5.1 客户 Customer

一个客户代表一家公司或业务主体。客户可以拥有多个联系人和多个产品项目。

| 分类 | 字段 |
|---|---|
| 基础信息 | 客户编号、国家、公司名称、客户类型、客户来源、负责人、备注 |
| 联系信息 | 主联系人、职位、邮箱、WhatsApp、电话；其他联系人独立保存 |
| 客户管理 | 客户等级、最近跟进日期、客户沉默天数、客户状态 |
| 招投标能力 | 政府招投标经验、投标资格、投标主体、当地执行团队、资金能力 |

客户等级固定为 A、B、C、D 四档。

### 5.2 项目 Opportunity

项目是“客户 + 产品机会”的独立记录。同一客户存在多个产品机会时，必须分别建立项目，避免不同产品的报价、样品和阶段相互覆盖。

| 分类 | 字段 |
|---|---|
| 产品机会 | 项目名称、产品大类、具体型号、适配设备品牌/型号、预计年用量 |
| 金额预测 | 预计项目金额、成交概率、加权预计销售金额、预计成交日期 |
| 供应商情况 | 当前供应商、当前采购品牌、当前采购价格、合作稳定程度、现有供应商问题、客户更换意愿、替代难度 |
| 我方方案 | 我方最新报价、客户目标价格、替代切入点、投入建议、是否需要样品/注册/授权 |
| 销售管理 | 当前阶段、最新反馈、当前阻碍、下一步行动、下次跟进日期、项目状态 |

销售阶段固定为：

新线索、已建立联系、需求确认、已报价、价格谈判、样品准备、样品测试、注册进行中、招标准备、等待订单、已成交、暂停、流失。

项目状态用于控制是否继续投入，至少包含：活跃、低频维护、暂停、已成交、已关闭。

### 5.3 联系人 Contact

字段包括姓名、职位、电话、邮箱、WhatsApp、沟通偏好、是否决策人、备注。一个客户可保存多个联系人，跟进记录可关联具体联系人。

### 5.4 跟进记录 Follow-up

每次联系新增一条记录，不允许用编辑旧记录代替新跟进。

| 字段 | 要求 |
|---|---|
| 跟进日期 | 必填，默认当前时间，可补录 |
| 客户/项目 | 必填，从现有数据选择 |
| 联系人/沟通方式 | 下拉或简短填写 |
| 本次沟通内容 | 简要记录 |
| 客户反馈 | 必填 |
| 客户态度 | 积极、正常、内部评估、拖延、已读未回复、明确拒绝 |
| 当前阶段 | 必填，默认项目当前阶段 |
| 下一步行动 | 必填 |
| 下次跟进日期 | 必填；选择“暂不跟进”时必须显式确认原因 |
| 负责人 | 默认项目负责人 |

保存后系统自动更新项目的最近跟进日期、最新反馈、当前阶段、下一步行动和下次跟进日期。

### 5.5 报价 Quote

字段包括报价编号、项目、版本、产品型号、数量、币种、单价、总金额、报价日期、有效期、客户是否收到、客户反馈、下一次跟进日期和结果。

报价不得只保留“最新报价金额”，历史版本必须可查询。

### 5.6 样品 Sample

字段包括项目、样品型号、数量、费用、寄出日期、物流公司、快递单号、签收日期、签收人、测试负责人、计划测试日期、测试状态、测试结果和下一步行动。

### 5.7 注册 Registration

字段包括项目、国家、注册要求、资料清单、资料状态、提交日期、预计完成日期、实际完成日期、费用承担方、状态、当前阻碍和下一步行动。

### 5.8 招标 Tender

字段包括项目编号、招标名称、截标日期、完整标书状态、投标资格、投标主体、保证金、客户经验、当地执行团队、资金能力、风险等级、授权类型、授权有效期、报价排他范围和下一步行动。

授权类型固定为：非独家项目授权、区域授权、暂不授权。

### 5.9 订单 Order

字段包括 PI/PO 编号、项目、订单日期、币种、订单金额、付款状态、生产状态、发货状态、预计到货日期、订单结果和预计复购日期。

订单状态不再用一个字段混合表达付款、生产和发货进度；三个进度应分别管理。

### 5.10 跟进计划 Task

任务可以由用户手工创建，也可以由报价、样品、招标、注册、订单和复购规则自动生成。

字段包括所属客户、所属项目、业务来源、计划时间、跟进原因、建议话术方向、下一步行动、负责人、状态、实际提醒时间和完成时间。

状态至少包括：待提醒、已提醒、已完成、已逾期、已取消。

## 6. 今日任务及看板

### 6.1 默认首页

打开应用后默认进入“今日任务”。系统自动列出今天到期和已经逾期的任务，不要求用户手工筛选。

每条任务至少显示：

- 客户名称和国家
- 项目及产品
- 最近反馈
- 跟进原因
- 建议话术方向
- 下一步行动
- 负责人
- 到期时间或逾期天数

任务按逾期程度、客户等级、项目重要程度和到期时间排序。暂停、流失、已关闭项目不生成高频任务。

### 6.2 业务异常入口

首页单独显示以下可点击分类：

- 报价后未回复
- 报价即将到期
- 样品已签收未测试
- 样品测试停滞
- 招标即将截止
- 注册节点到期
- 老客户即将复购
- 长期沉默客户
- 需要内部支持

### 6.3 管理统计

看板显示客户总数、A/B/C/D 数量、各阶段项目数、本周跟进数、报价停滞数、样品停滞数、未来三个月预计成交金额、未来三个月加权预计金额和已成交金额。

所有统计都必须可以下钻到对应记录列表，避免只显示不可解释的数字。

## 7. 自动任务与提醒规则

### 7.1 报价追踪

| 节点 | 自动任务 |
|---|---|
| 报价后 2 个工作日 | 确认客户是否收到报价 |
| 报价后 7 天 | 询问内部评估、价格反馈和采购计划 |
| 报价后 14 天 | 确认价格、规格、数量或决策流程中的实际阻碍 |
| 报价后 30 天无回复 | 标记“报价停滞”，重新评估项目真实性 |
| 报价后 60 天无回复 | 转入低频维护 |
| 报价有效期前 7 天 | 提醒是否更新报价 |

“工作日”按周一至周五计算，v2.0 不维护国家法定节假日日历。

### 7.2 样品测试

| 节点 | 自动任务 |
|---|---|
| 寄出后 | 跟踪物流 |
| 签收后 3 天 | 确认样品完整及接收人 |
| 签收后 7 天 | 确认测试负责人和测试计划 |
| 签收后 14 天 | 确认测试是否开始 |
| 签收后 30 天无反馈 | 标记“样品停滞” |
| 测试通过后 3 天 | 推进报价、注册、授权及首单 |

### 7.3 常态化跟进

| 客户等级/状态 | 建议频率 |
|---|---|
| A 级 | 每 7–14 天一次 |
| B 级 | 每 21–30 天一次 |
| C 级 | 每 45–60 天一次 |
| 已成交 | 预计复购日期前 30 天 |
| 长期沉默 | 每月提示是否重新激活 |
| D 级、明确拒绝、无真实需求 | 停止高频跟进，转为低频或关闭 |

系统提供建议日期，但用户仍可调整；自动规则不得生成内容和日期完全相同的重复任务。

### 7.4 招标提醒

截标日期前 30、14、7、3、1 天自动生成任务。已经关闭、放弃或未通过资格核验的招标不再生成后续提醒。

### 7.5 注册与复购提醒

- 注册按预计完成日期、资料待补日期和用户设置的关键节点生成提醒。
- 已成交订单按预计复购日期提前 30 天生成提醒。
- 复购完成并产生新订单后，旧复购任务自动完成，下一次复购日期重新计算或由用户确认。

## 8. 供应商替代决策

### 8.1 结构化判断

当前供应商问题固定选项包括：价格高、质量问题、交期不稳定、型号不完整、注册文件不足、服务慢、MOQ 高、暂无明显问题、尚未确认。

客户更换意愿包括高、中、低、未确认；替代难度包括容易、中等、困难。

推荐切入点包括：价格替代、第二供应商、连接管切入、非核心型号切入、样品测试、OEM、注册合作、新招标、补充缺失型号、暂不推进。

投入建议包括：继续投入、限制样品投入、先确认订单、暂不承担注册费用、暂停跟进。

### 8.2 自动建议规则

- 供应商关系稳定且无明显问题：不建议正面替代，优先第二供应商或补充型号方案。
- 当前价格明显偏高：建议同规格价格对比，但价格支持必须与数量或订单承诺绑定。
- 客户与 Medtron 等设备品牌合作：优先从连接管、Patient Line 或非冲突耗材切入。
- 客户长期使用 Antmed 等成熟供应商：先确认不满点和切换意愿，再决定是否安排样品。
- 客户只有询价、没有明确需求：先补充设备型号、年用量、采购时间和当前供应商，不自动建议降价。
- 客户首次参加政府招标：默认风险“中高”，仅建议限定项目、限定期限的非独家授权。

自动建议必须展示触发依据，并允许用户手工覆盖；系统不代替销售作最终商业决策。

## 9. 跟进理由与话术方向

系统根据项目阶段和时间节点生成建议：

| 阶段 | 建议重点 |
|---|---|
| 新线索 | 设备品牌/型号、经营品牌、现有供应商、医院覆盖和产品需求 |
| 需求确认 | 年用量、具体型号、采购时间、注册要求 |
| 已报价/价格谈判 | 是否收到、内部反馈、目标价格、竞争价格和决策时间 |
| 供应商替代 | 现有供应商痛点、第二供应商或非核心型号切入方案 |
| 样品准备/测试 | 物流、签收、测试负责人、测试日期、初步结果和正式报告 |
| 注册/招标 | 文件截止、投标主体、资质、保证金、授权和项目时间表 |
| 等待订单 | PI/PO、付款安排、采购审批和预计下单时间 |
| 已成交 | 库存、销售速度、终端反馈和下一次补货时间 |

建议话术只提供方向，不自动生成或发送对外消息。

## 10. 自动计算与视觉规则

系统自动计算：

- 任务逾期天数
- 客户沉默天数
- 报价后未回复天数
- 样品签收后未测试天数
- 加权预计销售金额 = 预计项目金额 × 成交概率
- 未来三个月预计金额和加权预计金额
- 客户累计成交金额

列表视觉规则：

- 已逾期：红色语义提示
- 3 天内到期：黄色语义提示
- 已完成：绿色语义提示
- 暂停/流失/关闭：灰色弱化
- A 级客户、重大项目、未来三个月预计成交项目：突出显示

颜色不能作为唯一状态表达，必须同时显示文字、图标或状态标签；深色模式下保持可读性。

## 11. 客户分级

| 等级 | 判断标准 | 管理方式 |
|---|---|---|
| A | 明确需求或采购量；设备与供应商已确认；已提出报价、样品、注册或授权；存在决策人或近期采购计划 | 重点跟进，7–14 天一次 |
| B | 产品匹配且有回复，但需求、数量或时间尚未完全明确 | 持续培育，21–30 天一次 |
| C | 公司匹配，但长期不回复或暂时无项目 | 低频维护，45–60 天一次 |
| D | 真实性不足、只索取价格/授权、无采购能力、多次承诺无行动或明确拒绝 | 限制投入或关闭 |

等级默认手工确认。系统可根据结构化信息提示升级或降级，但不得静默修改。

## 12. 政府招投标控制

- 首次投标客户默认风险为“中高”。
- 授权和底价支持前，必须完成投标资格、投标主体、保证金、当地执行团队和资金能力核验。
- 完整标书未取得时，不得把项目标记为“资格核验完成”。
- 报价存在排他条款时，必须记录排他范围、有效期以及是否允许向其他投标商报价。
- 授权必须关联具体项目和有效期，不允许只在客户备注中记录。
- 高风险项目在授权或底价确认前显示明确警告，但不实现多人审批流。

## 13. 搜索、筛选与排序

客户及项目列表至少支持：

- 国家
- 产品大类和具体型号
- 适配设备品牌
- 当前供应商
- 替代切入点
- 销售阶段
- 客户等级
- 项目状态
- 负责人
- 预计成交日期
- 报价停滞、样品停滞、长期沉默

默认排序为：逾期任务优先，其次 A 级和重大项目，再按下次跟进日期升序。

## 15. 数据安全、附件与导出

### 15.1 附件

报价、样品、注册、招标、订单和跟进记录均可挂附件。来源支持拍照、相册和系统文件选择器。

文件保存在应用私有目录，数据库只保存相对路径、原始文件名、类型和大小。图片长边压缩到不超过 1920px，并尽量控制在 500KB 内。删除业务记录时同步删除其附件文件。

实现状态（2026-08-06）：六类已持久化记录已接入统一附件页；草稿保存前不允许挂附件。数据库删除先提交，物理文件随后清理，失败项在下次启动通过孤儿扫描重试。自动化与 Android API 37 模拟器通用链路证据见 `docs/phase4/VERIFICATION.md`；相机和一加 13 / ColorOS 15 文件提供器兼容性仍属于目标真机发布门槛。

### 15.2 备份恢复

备份产物为 zip，包含 `data.json`、数据库结构版本、全部附件和校验清单。恢复前先验证结构版本与文件完整性，恢复后重建未来提醒。

实现状态（2026-08-06）：已接入设置页。备份 ZIP 包含 `customer.sqlite`、`data.json`、附件文件、schema version 和 SHA-256 校验清单；恢复会先校验 SQLite 完整性、数据快照和附件路径，再在下次启动原子替换数据库与附件目录。应用启动已有全量 `rescheduleAll()`，因此恢复后的未来提醒会随数据库重新排程。真机文件提供器和提醒可靠性仍属于发布验收项。

### 15.3 Excel 导出

Excel 导出至少包含四张工作表：今日任务及看板、客户及项目、跟进记录、报价/样品/订单追踪。

导出文件要求：中文无乱码、首行冻结、可筛选、日期与金额格式正确、状态具备条件格式、公式结果可在常见 Excel 软件中打开。导出用于查阅和分析，不用于恢复，也不允许回写覆盖 App 数据。

## 16. 非功能需求

### 16.1 提醒可靠性

- Android 10 及以上可用。
- 锁屏、断网、应用进程退出和设备重启后仍能触发未来提醒。
- 在目标机型一加 13、ColorOS 15 上连续 7 天的有效提醒触发率达到 100%，允许误差不超过 60 秒。
- 通知点击直达对应项目或任务；通知支持“已完成”和“推迟一天”。
- 记录计划时间、实际触发时间和偏差，用于可靠性自查。

### 16.2 性能

- 500 个客户、1500 个项目、5000 条跟进记录下，核心列表查询低于 200ms。
- 搜索和筛选操作 200ms 内返回首批结果。
- 冷启动 2 秒内显示本地首屏内容。

### 16.3 易用性

- 常用选择使用固定选项或下拉菜单。
- 跟进记录保留 5 个核心更新项的快速路径。
- 320px 宽度和系统深色模式下无文字溢出。
- 破坏性操作必须二次确认；自动建议和自动任务必须可解释、可调整。

## 17. 验收标准

1. 打开应用后，“今日任务”立即显示今天和逾期任务。
2. 每个任务显示客户、项目、跟进原因、下一步行动和负责人。
3. 销售完成一次日常跟进，只需更新 5 个核心字段。
4. 跟进记录新增后，项目的最近日期、反馈、阶段、下一步和下次跟进日期自动同步。
5. 报价、样品、复购和招标提醒按规定节点自动生成且不重复。
6. 可以按供应商、替代切入点、阶段、等级、国家和负责人筛选。
7. 系统能识别报价停滞、样品停滞、长期沉默和建议限制投入的项目。
8. 预计金额、成交概率和加权预计金额计算正确。
9. 报价版本、样品节点、跟进记录和阶段变化可追溯。
10. 招标资格、授权类型、风险和排他条款可完整记录。
11. 订单、付款、生产、发货和预计复购可以分别追踪。
12. 9 条示例数据覆盖指定业务场景，且可整体撤销。
13. Excel 导出包含四张核心工作表，中文、筛选、格式和公式正常。
14. 完整备份可恢复全部业务数据和附件，恢复后未来提醒重新生效。
15. 在一加 13、ColorOS 15 上完成提醒可靠性真机验收。
16. `flutter analyze`、全部自动化测试和 release APK 构建通过。

## 18. 分阶段实施边界

现有 v1 数据层和界面不满足“客户 + 多项目”的业务模型，v2 实施必须先完成数据库迁移，再扩展页面，不能直接把所有新字段继续堆入客户表。

### 阶段 A：需求基线与迁移设计

- 冻结本 SPRD。
- 明确旧客户、联系人、跟进、计划和订单向 v2 模型的映射。
- 为旧数据制定可回滚的数据库迁移测试。

### 阶段 B：客户项目主线

- 新增项目实体和完整外贸字段。
- 扩展客户、联系人、A/B/C/D 分级与 13 个销售阶段。
- 把旧订单和跟进记录关联到项目。

### 阶段 C：跟进与今日任务

- 落地 5 字段快速跟进。
- 同步项目最新状态。
- 升级任务模型、首页字段和管理统计。

### 阶段 D：报价、样品与业务规则

- 新增报价与样品实体、历史记录和自动任务规则。
- 实现停滞判断、到期提醒与供应商替代建议。

### 阶段 E：注册、招标、订单与复购

- 新增注册和招标实体。
- 拆分订单付款、生产、发货状态。
- 实现招标节点和复购提醒。

### 阶段 F：附件、示例、导出与备份

- 将附件能力接入全部业务对象。
- 提供可撤销示例数据。
- 完成四表 Excel 导出、完整备份恢复和使用说明。

### 阶段 G：验收与发布

- 完成自动化、模拟器和目标真机验收。
- 完成数据迁移演练、性能测试和 release 构建。

## 19. 明确不做

- 多用户账号、团队协作、客户分配和角色权限
- 云端同步、Web 后台和实时在线协作
- 自动发送 WhatsApp、邮件或其他对外消息
- 国家法定节假日工作日历
- 复杂 CPQ、税务、发票和财务系统对接
- AI 自动替代销售作报价、授权或投入决策
- Google Sheets 双向同步或将其作为主数据库

以上能力如需增加，应作为独立版本评估，不得在 v2.0 实施中隐式扩张范围。
