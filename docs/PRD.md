# 客户跟进助手 PRD

版本 v1.0　　最后更新 2026-08-04

## 1. 产品定位

一款**单人本地使用**的 Android 客户跟进工具。核心价值是「不漏跟进」，而不是「管理销售团队」。

数据全部存在手机本地 SQLite，不联网、不注册、不上传。这是设计前提，不是待办事项。

### 一句话描述

帮一个销售记住每个客户该在什么时候被联系，并且到点一定会响。

## 2. 竞品调研结论

调研了三类产品，结论直接影响功能取舍。

**企业级 CRM（纷享销客、销售易）**

功能清单里超过一半是管理者视角：线索自动分配与回收、保有量规则、销售行为管控、商机报备防撞单、团队目标设定、BI 多维看板、CPQ 复杂报价、业财一体化。这些能力的前提是「有多个销售 + 有管理者」，单人场景下全部归零。

值得借鉴的只有三点：客户 360 视图的信息聚合思路、客户分级与标签、客户从线索到成交的阶段流转。

**个人 PRM（Monica）**

定位是记录人际关系，提醒机制做得扎实（含生日自动提醒），交互极简。但它没有金额、订单、成交阶段的概念，纯记录不驱动业务。

值得借鉴：提醒是一等公民、单人单库不做权限、信息录入路径极短。

**取舍判断**

本产品 = Monica 的轻量与提醒可靠性 + 企业 CRM 的「客户阶段 + 订单」主线。

## 3. 明确不做的功能

这一节和功能清单同等重要，用于抵抗后续范围膨胀。

- 多用户、账号体系、登录注册
- 权限、角色、数据可见范围
- 团队协作、客户分配、审批流
- 云端同步、服务端、Web 后台
- 线索池、自动分配回收、保有量规则
- 复杂报价 CPQ、多币种、发票与财务对接
- BI 报表平台、自定义报表
- 社交属性、消息推送到他人
- 周期性与重复提醒（含生日提醒），仅做一次性提醒

以上任何一项若未来要做，视为 v2 立项，不在本 PRD 范围。

## 4. 目标用户与核心场景

使用者是你自己：一个需要维护几十到几百个客户的销售。

**场景 A　展会现场加了新客户**

走出展台后 30 秒内录完：公司名、姓名、电话、一句备注、设一个「三天后跟进」。要求录入路径不超过 4 次点击，电话可从通讯录选。

**场景 B　早上出门前看今天要做什么**

打开应用第一屏直接看到「今天该联系的 5 个客户」，按紧急度排序，逾期的排最前面并有明显视觉区分。

**场景 C　打完电话记一笔**

从今日待办点进客户，两次点击内写完沟通内容，同时决定下次什么时候再跟。不能出现「记完跟进却忘了设下次提醒」的断点。

**场景 D　到点被提醒**

手机锁屏状态、应用被杀、断网、重启过，提醒都必须准时响。这是产品的生死线。

**场景 E　老客户复购**

查某个客户历史买过什么、金额多少、上次成交多久之前，决定是否该推新单。

## 5. 功能需求

### 5.1 客户管理

客户是核心实体。字段分必填与选填两层，避免录入负担。

必填只有一项：客户名称。其余全部选填，包括公司、电话、微信、地址、来源渠道、备注。

客户携带三个结构化属性：

- **阶段**：潜在客户 / 已接触 / 意向明确 / 已成交 / 已流失。五档够用，不做自定义阶段。
- **分级**：A / B / C 三档，手动打标，用于列表排序权重。
- **标签**：自由多选，如「价格敏感」「决策人」「同行推荐」。

客户列表需支持：按跟进紧急度排序（默认）、按阶段筛选、按标签筛选、按名称与电话模糊搜索。列表每行显示客户名、阶段、下次跟进时间、逾期天数。

一个客户可挂多个联系人，联系人含姓名、职位、电话、是否决策人。

### 5.2 跟进记录

每条跟进记录包含：发生时间、方式（电话 / 微信 / 面谈 / 其他）、沟通内容、本次结论。

客户详情页以时间线形式倒序展示全部跟进记录。

**关键设计**：新增跟进记录时，界面底部固定一个「设置下次跟进」区块，提供快捷选项（明天 / 三天后 / 一周后 / 一个月后 / 自定义）。不设置需要显式点击「暂不跟进」，避免无意识跳过。

### 5.3 跟进计划与提醒

跟进计划是独立实体，不是客户表上的一个时间字段。原因是一个客户可能有多条并行待办（催合同、送样品、节日问候），且提醒本身需要状态机。

跟进计划字段：所属客户、计划时间、事项标题、状态。

状态机：待提醒 → 已提醒 → 已完成，或 待提醒 → 已逾期。逾期定义为超过计划时间 24 小时未标记完成。

提醒一律为一次性，不做重复与周期性提醒。需要下次跟进时，由用户在处理当前跟进后手动设定新的计划，这与 5.2 的强制决策设计相互配合。

提醒要求：

- 本地精确闹钟，断网可用
- 通知点击直达对应客户详情页
- 通知内可直接标记「已完成」或「推迟一天」
- 设备重启后自动重建全部未来闹钟
- 首次启动引导用户授予通知权限、精确闹钟权限、电池优化白名单
- 记录每次提醒的实际触发时间，供可靠性自查

**目标机型适配**

主力设备为一加 13，系统 ColorOS 15（Android 15）。ColorOS 的后台管控较为激进，需针对性处理以下四项，缺一项都可能导致提醒静默失败：

- 电池优化白名单，引导至「设置 - 电池 - 耗电管理」将本应用设为不受限制
- 自启动权限，ColorOS 单独管理，与电池白名单是两个开关
- 「允许后台弹出界面」权限，否则通知点击后可能无法拉起页面
- 锁屏通知与横幅通知开关，确保锁屏状态可见

引导流程需能直接跳转到 ColorOS 对应设置页，而非仅给文字说明。跳转失败时回退到系统应用详情页并给出图文步骤。

### 5.4 订单管理

订单归属于客户，字段：订单编号（可自动生成）、下单日期、金额、商品或服务描述、状态。

状态流转：待确认 → 已发货 → 已收款 → 已完成，另设「已取消」终态。

客户详情页展示该客户订单列表与累计成交金额。

### 5.5 附件

订单与跟进记录均可挂附件，典型用途是合同照片、报价单、样品照片、名片。

来源支持拍照与从相册选择，以及从系统文件选择器选取 PDF 等文档。

文件存储在应用私有目录下，数据库仅保存相对路径、原始文件名、类型与大小。不使用绝对路径，否则应用重装或系统迁移后全部失效。

图片在保存时压缩到长边不超过 1920px，避免几十张合同照片迅速吃掉存储。原图不保留。

附件可预览、可删除。删除记录时其附件文件一并物理删除，不留孤儿文件。

由于附件是二进制文件，它对备份方案有直接影响，见 5.7。

**实现说明**　拍照与相册选择用 `image_picker`。文档选择原计划用 `file_picker`，
但该包与其他依赖存在 win32 版本冲突（详见 TECH_STACK.md 第 3 节），改用 Android
原生 `ACTION_OPEN_DOCUMENT` intent 实现，能力等价。

### 5.6 新客户开发视图

一个按阶段分组的漏斗视图，展示各阶段客户数量，点击某阶段进入该阶段客户列表。

同时提供「久未联系」提示：超过 30 天无跟进记录且阶段非「已成交」「已流失」的客户，集中列出。这是防止客户静默流失的兜底机制。

### 5.7 数据安全与备份

纯本地存储，因此备份责任在应用自身。

因为引入了附件，备份不能只导出结构化数据。导出产物为一个 zip 包，内含 `data.json`（全部表数据）与 `attachments/` 目录（全部附件文件）。恢复时解压还原数据并重建附件路径映射。

同时提供一个纯 Excel 导出，仅含客户、跟进、订单三张主表，用于人工查阅和在电脑上做表格分析。它不用于恢复，只用于阅读。

备份不是可选项。单机应用一旦丢数据无法找回。

## 6. 非功能需求

**提醒可靠性**：连续 7 天内设置的提醒，实际触发率需达到 100%。这是唯一的硬性指标。

**性能**：500 个客户、5000 条跟进记录规模下，列表滚动无掉帧，搜索响应 200ms 内。

**冷启动**：2 秒内可见首屏内容。

**离线**：全部功能在飞行模式下可用。

**兼容**：Android 10 及以上。

**存储占用**：附件压缩后，单张照片控制在 500KB 以内。

## 7. 技术方案

详细的技术选型、完整依赖清单与版本号见 [TECH_STACK.md](TECH_STACK.md)。UI 设计规范与设计常量见 [UI_GUIDELINES.md](UI_GUIDELINES.md)。

核心决策摘要：

- Flutter 3.44.8 + Material 3，不引入第三方 UI 组件库
- 状态管理 riverpod 3.3.2，路由 go_router 17.3.0
- 本地库 drift 2.34.3 + sqlite3 3.5.0（注意 `sqlite3_flutter_libs` 已 EOL，不再使用）
- 提醒 flutter_local_notifications 22.2.0 + android_alarm_manager_plus 5.1.1
- 依赖版本全部写死，不用 `^` 范围
- 金额存整数分，时间存 UTC 毫秒时间戳

## 8. 分阶段计划与验收标准

每个阶段都必须能真实运行并通过验收才进入下一阶段。验收标准写成可执行的检查项，不用「基本完成」这类模糊表述。

### 阶段 0　环境与骨架

**范围**：补齐 JDK 环境变量与 Android cmdline-tools，创建项目，按 TECH_STACK.md 装齐依赖，搭好 tokens.dart / theme.dart 与底部导航空壳。

**验收标准**

1. `flutter doctor` 无 Android 相关报错，license 检查通过
2. `pubspec.yaml` 依赖与 TECH_STACK.md 第 3 节完全一致，版本号无 `^`
3. `flutter pub get` 与 `build_runner` 均成功执行
4. `flutter build apk --debug` 成功产出 APK
5. APK 安装到 Pixel_8 模拟器可启动，底部四个 Tab 可切换且不崩溃
6. `tokens.dart` 已按 UI_GUIDELINES.md 定义间距、圆角、字号、语义色常量
7. `theme.dart` 用 `ColorScheme.fromSeed` 生成明暗两套主题，切换系统深色模式应用跟随变化
8. 首页所有间距与字号均引用常量，无字面量数字

### 阶段 1　数据层

**范围**：drift 建表（客户、联系人、跟进记录、跟进计划、订单、标签、客户标签关联、附件），写 DAO 与迁移策略。

**验收标准**

1. 八张表建表成功，外键约束生效
2. 单元测试覆盖每张表的增删改查，全部通过
3. 单元测试验证级联删除：删除客户后其联系人、跟进记录、跟进计划、订单、附件记录一并删除
4. 写入 500 客户 + 5000 跟进记录的性能测试，按紧急度排序查询耗时低于 200ms
5. 数据库版本号与迁移函数已就位，能从 v1 空库正常初始化
6. 附件表仅存相对路径，单元测试验证路径拼接函数在应用目录变化后仍能正确解析

### 阶段 2　提醒链路（关键里程碑）

**范围**：权限引导、闹钟调度、通知展示与交互、重启恢复、触发日志。此阶段不做任何界面美化。

**验收标准**

1. 首次启动依次引导通知权限、精确闹钟权限、电池优化白名单、ColorOS 自启动、后台弹出界面权限，拒绝后有明确的再次引导入口
2. 设置 5 分钟后的提醒，锁屏状态下准时弹出通知，误差不超过 60 秒
3. 从任务管理器强制杀掉应用后，提醒仍准时触发
4. 开启飞行模式后，提醒仍准时触发
5. 重启手机后，此前设置的未来提醒全部仍能触发
6. 点击通知直达对应客户详情页
7. 通知上的「已完成」「推迟一天」操作生效，数据库状态同步更新
8. **在一加 13 真机上连续验证 3 天，每天设置至少 2 个提醒，触发率 100%**
9. 提醒触发日志可在应用内查看，含计划时间与实际触发时间
10. 权限引导能实际跳转到 ColorOS 对应设置页；跳转失败时回退到应用详情页并展示图文步骤
11. 设置一个次日早晨的提醒，手机整夜息屏充电，验证在 ColorOS 深度睡眠下仍准时触发

第 8 项是硬门槛。未通过则不进入阶段 3，需重新评估技术方案。

### 阶段 3　客户与跟进主流程

**范围**：客户列表、客户新增与编辑、客户详情、联系人管理、跟进记录时间线、今日待办首页。

**验收标准**

1. 新增客户仅填名称即可保存成功
2. 从首页到完成一个新客户录入（含设置首次跟进）不超过 4 次点击
3. 客户列表默认按紧急度排序，逾期客户排最前且有明确视觉区分
4. 阶段筛选、标签筛选、名称与电话搜索均生效
5. 新增跟进记录后，未设置下次跟进时必须显式点击「暂不跟进」才能保存
6. 客户详情时间线倒序展示全部跟进记录
7. 电话字段支持一键拨号，支持从系统通讯录导入
8. 500 客户数据下列表滚动无可感知卡顿
9. 深色模式下所有页面文字与背景对比度达标，无文字溢出容器

### 阶段 4　订单与开发漏斗

**范围**：订单增删改查、状态流转、客户累计金额、附件上传与预览、阶段漏斗视图、久未联系提示。

**验收标准**

1. 订单可创建并在客户详情页正确归属
2. 订单状态按定义流转，非法流转被阻止（如已取消不能改为已发货）
3. 客户详情页累计成交金额计算正确，仅统计「已完成」状态订单
4. 漏斗视图各阶段客户数与实际数据一致，点击可下钻到列表
5. 久未联系列表正确排除「已成交」「已流失」客户
6. 订单与跟进记录均可添加附件，拍照、相册、文件三种来源都能成功
7. 上传一张 4000px 宽的照片，压缩后长边不超过 1920px 且文件小于 500KB
8. 附件可预览，图片能放大查看，PDF 能调用系统应用打开
9. 删除一条带附件的订单后，其附件文件在私有目录中确实被物理删除

### 阶段 5　备份与收尾

**范围**：数据导出导入、图标与应用信息、release 包签名。

**验收标准**

1. 导出 zip 包含 `data.json`（全部八张表）与 `attachments/` 目录，可解压人工检视
2. 清空应用数据后从 zip 完整恢复，客户数、跟进记录数、订单数、附件数与导出前一致
3. 恢复后附件可正常预览，路径映射正确无失效文件
4. 恢复后此前设置的未来提醒重新生效
5. Excel 导出能在电脑上正常打开，中文无乱码
6. `flutter build apk --release` 成功，已签名，安装到一加 13 可正常启动
7. 应用图标与名称已替换，非默认 Flutter 图标

## 9. 推进顺序说明

阶段顺序不可调换，尤其是阶段 2 必须排在界面之前。

理由是提醒可靠性受 Android 系统与国产 ROM 限制，存在无法通过代码完全解决的风险。若把它放在最后，可能出现所有界面都做完才发现提醒不可靠的局面，届时技术选型的返工成本极高。先验证风险最高的部分，是这个项目唯一正确的顺序。

## 10. 已确认的关键决策

1. **目标设备**：一加 13 / ColorOS 15。权限引导按 ColorOS 适配，需处理电池白名单、自启动、后台弹出界面、锁屏通知四项。
2. **提醒形态**：仅一次性提醒，不做生日与周期性提醒。下次跟进由用户在处理完当前跟进时手动设定。
3. **附件**：需要。订单与跟进记录均可挂附件，支持拍照、相册、文件三种来源，图片压缩后存入应用私有目录，备份产物因此改为 zip 包。
