# 本期需求：长表单首个错误自动定位

日期：2026-08-07

## 背景

订单、跟进、项目和招标表单均可能超过一屏，主要保存按钮固定在底部。当前校验失败只显示字段错误或 SnackBar，用户仍需自行向上查找；招标的保证金和风险确认还可能位于已收起区块中。订单和跟进在个别前置选择为空时会提前返回。订单和项目还使用惰性长列表，滚到底部后顶部字段可能已离开 Form 树，导致保存时未被校验。

## 目标

- 保存失败时自动定位到用户最先需要处理的字段。
- 确保长表单的校验字段在保存时仍处于 Form 树中。
- 文本输入错误在滚动完成后获得输入焦点。
- 错误位于招标折叠区时先展开对应区块，再滚动定位。
- 保持服务校验、数据库、路由和保存成功行为不变。

## 交互规则

1. 订单按“关联项目、订单号、订单金额”的页面顺序定位首个错误；文本错误获得焦点。
2. 跟进按“客户反馈、项目阶段、下一步行动、暂停原因”的页面顺序定位首个错误；文本错误获得焦点。
3. 项目名称为空或页面可识别的数字/金额格式错误时，定位并聚焦对应字段。
4. 招标保证金无效时自动展开“资格核验”，定位并聚焦保证金；缺少高风险确认时自动展开“授权与风险”并定位确认项。
5. 定位使用短时平滑滚动，目标靠近屏幕上部并保留上下文。
6. 校验失败不清空输入、不离开页面，也不关闭未保存修改保护。

## 不在本期

- 不改变字段必填性、金额单位、风险规则或服务端错误文案。
- 不重做表单布局或折叠区视觉样式。
- 不处理本身不超过一屏的客户、联系人和新增报价表单。
- 不包含 OnePlus/ColorOS 真机验证。

## 验收标准

1. 四个长表单均能在保存失败后把首个可处理错误带入视口。
2. 订单、跟进、项目和招标的文本错误字段获得焦点。
3. 招标资格与风险区可因错误自动展开。
4. 原有错误文案、保存逻辑和退出保护无回归。
5. 聚焦 UT、全量 UT、静态分析、release APK 构建和 Android 模拟器安装启动验证通过。
6. 仓库说明书与应用内使用说明同步。
