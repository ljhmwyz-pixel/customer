# 阶段 E-5.2：订单生命周期表单实施计划

## 目标

在现有订单新增/编辑表单中接入已经落库的完整生命周期字段，使用户可以维护 PI/PO、币种、收款、生产、发货、预计到货、订单结果和预计复购信息，同时保持旧订单聚合状态及既有推进流程兼容。

## 边界

- 修改 `lib/features/orders/order_form_page.dart`，不调整数据库 schema、DAO 或服务层。
- 保留现有 `order-status` 只读字段；生命周期字段由 DAO 继续映射为旧聚合状态。
- 使用服务层已有校验，并在表单中用 SnackBar 展示日期、币种等业务错误。
- 为全部新增控件提供稳定 key，便于自动化测试和后续维护。

## 实施步骤

1. 扩展订单页面测试，覆盖新增订单保存完整生命周期字段，以及编辑订单回填并更新这些字段。
2. 先运行页面测试，确认因生命周期控件尚不存在而按预期失败。
3. 为表单添加字段状态、编辑回填、日期选择/清除、保存参数和 controller 释放逻辑。
4. 运行订单页面、订单服务及业务任务规则定向测试，再运行静态分析和全部测试。
5. 检查 diff，仅暂存本阶段三个文件并提交为 `阶段 E-5.2：完善订单生命周期表单`。

## 验收标准

- 新增订单可保存全部生命周期字段，币种由服务层规范为三位大写字母。
- 编辑订单可正确回填并更新全部生命周期字段。
- 可选日期可选择和清除，非法日期关系会显示服务层错误且不退出表单。
- 旧 `order-status`、订单推进和累计成交额行为不回归。
- `flutter analyze`、全部测试和 Git whitespace 检查通过。
