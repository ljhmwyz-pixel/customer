# Phase E Dashboard Business Anomalies Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add due registration milestones, imminent tender reminders, and due repurchase reminders to the management dashboard with customer-context navigation.

**Architecture:** Extend the existing typed dashboard anomaly contract and its Drift-backed union query. Reuse open automatic tasks in `follow_plans` as the source of truth, so the dashboard does not duplicate registration, tender, or repurchase date calculations; the page maps each anomaly kind to explicit copy and an icon, then navigates to the existing customer detail route.

**Tech Stack:** Flutter 3.44.8, Dart 3.12.2, Material 3, Riverpod 3.3.2, Drift 2.34.3, SQLite, flutter_test.

## Global Constraints

- Include only `registration`, `tender`, and `repurchase` task sources.
- Include only `pending`, `notified`, and `overdue` task statuses with `plan_at <= now`.
- Exclude completed, cancelled, and future tasks.
- Sort business task anomalies by `plan_at ASC, follow_plans.id ASC` so the earliest due item appears first.
- Use non-blank `next_action` as detail and fall back to the task title.
- Preserve customer and opportunity context from the task; navigation target is `/customers/{customerId}` because no standalone opportunity detail route exists.
- Preserve the existing long-silence and internal-support rules.
- Remove the stale registration/tender/repurchase unavailable copy; quote and sample behavior is out of scope.
- Add no dependency, schema migration, new business rule, or new route.
- Stage only files changed by this phase and do not push.
