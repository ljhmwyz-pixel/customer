# 本期需求：弹窗宽度一致性

日期：2026-08-08

## 背景

应用内确认、退出保护、删除和导入纠错等交互均使用 Material `AlertDialog`，颜色、圆角、阴影、边距和最大宽度已经由全局主题统一。但主题没有定义最小宽度，内容较短的弹窗会按内容收缩，视觉上明显窄于其他弹窗，也降低按钮和文案的可读性。

## 目标

通过全局主题统一标准弹窗的可读宽度，使短内容与长内容弹窗保持稳定观感，同时兼容窄屏和明暗主题。

## 范围

- 标准 `AlertDialog` 在空间充足时最小宽度为 360dp，最大宽度为 420dp。
- 屏幕不足 392dp 时，弹窗由系统约束自动缩小，并保留左右各 16dp 安全边距。
- 浅色和深色主题使用完全相同的宽度约束。
- 现有确认、退出保护、删除和编辑弹窗自动继承主题，不逐页增加尺寸常量。
- 将弹窗尺寸约束同步到 UI 设计规范、仓库使用说明书和应用内使用说明。

## 不在本期

- 不重写现有弹窗的业务流程、文案和按钮顺序。
- 不为个别页面引入自定义弹窗容器。
- 不调整日期选择器、系统文件选择器、底部抽屉或菜单的尺寸。
- 不包含物理设备验证；Android 模拟器验证仍需完成。

## 交互约束

- 短标题、短正文弹窗不得因内容少而收缩成窄条。
- 弹窗不得越过屏幕边缘或产生横向布局溢出。
- 窄屏适配应由父级可用空间自然限制，不允许通过横向滚动解决。
- 现有圆角、阴影、内容间距和操作按钮样式保持不变。

## 验收标准

1. 浅色和深色 `DialogTheme` 的最小宽度均为 360dp、最大宽度均为 420dp。
2. 在 412dp 宽视口中，只有短标题和短正文的 `AlertDialog` 宽度不小于 360dp。
3. 在 320dp 宽视口中，弹窗宽度不超过 288dp，左右各保留至少 16dp，且无布局异常。
4. 短内容和较长内容弹窗在常规手机宽度下使用相同的稳定宽度约束。
5. 现有弹窗无需单独修改即可继承统一尺寸。
6. 全量测试、静态分析、release APK 构建和 Android 模拟器启动验证通过。
7. UI 规范、仓库说明书和应用内说明书均同步本期交互规则。
