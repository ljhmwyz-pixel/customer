# 本期需求：导入预览纠错与行排除

日期：2026-08-07

## 背景

客户/联系人导入已经支持 Excel、CSV、预览、校验和事务写入，但错误预览只显示行号与错误文本。用户发现错误后只能离开应用修改原文件、重新选择并再次解析；同一行有多个问题时还会重复展示，纠错路径较长。

## 目标

让用户在导入预览中直接看清问题字段和当前值，能够在应用内修正错误行或明确排除不需要的行，并在每次操作后立即重新校验，直到文件可以安全导入。

## 范围

- 校验问题携带字段名，预览按源文件行号归组展示。
- 错误行显示客户名称、客户编号以及该行全部问题，避免同一行重复占用列表。
- 支持在应用内修正当前校验涉及的字段：客户编号、客户名称、联系人邮箱、客户阶段、客户等级。
- 修正后保留原始行号，并对全部保留行重新校验；重复编号等跨行问题必须随之更新。
- 支持确认后排除不需要导入的错误行；排除后重新校验剩余行。
- 仍有问题时明确提示“修正或排除后可导入”，并禁用确认导入。
- 全部问题解决后展示可导入状态并启用确认导入。
- 保持现有数据库事务、客户匹配、联系人匹配和导入结果统计不变。

## 不在本期

- 不提供完整电子表格编辑器，不允许编辑与错误无关的全部 26 个字段。
- 不自动猜测或静默修正客户阶段、等级、邮箱和重复编号。
- 不允许跳过错误后继续部分导入；只有保留行全部通过校验才可导入。
- 不改变 Excel/CSV 模板、数据库结构、重复匹配规则或业务记录范围。
- 不包含 OnePlus/ColorOS 真机验证。

## 交互约束

- “修正本行”是错误行的主要操作，“不导入此行”是次要且需要确认的破坏性操作。
- 修正弹窗只展示当前错误涉及的字段，避免形成密集表格。
- 客户阶段和客户等级使用选项控件；名称、编号和邮箱使用文本输入。
- 所有操作在窄屏和深色模式下不得溢出，按钮触控区域不小于 44dp。
- 排除最后一行后显示空预览状态，不能导入。

## 验收标准

1. 每个校验问题包含准确字段名，重复客户编号指向“客户编号”。
2. 修改错误行后保留行号和其他字段，并基于所有行重新计算问题。
3. 将缺失客户名称、无效邮箱、阶段或等级修正为有效值后，相应问题消失。
4. 修改或排除重复编号行后，跨行重复问题消失。
5. 排除行必须二次确认，取消确认时预览不变化。
6. 保留行仍有问题时确认导入不可用；问题全部解决且至少保留一行时可用。
7. 修正后的预览传入既有 `importPreview` 后，按修正值完成事务导入。
8. 仓库说明书与应用内说明书同步说明应用内纠错和行排除能力。
