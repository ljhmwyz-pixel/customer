# 本期需求：客户、联系人和新增报价表单安全补齐

日期：2026-08-07

## 背景

项目、跟进、订单及主要业务节点已经具备未保存修改保护，但客户、联系人和新增报价仍可能因误触返回丢失输入。同时，现有保护采用“发生过修改”的标记方式，无法区分用户是否已把字段恢复为进入页面时的值。

## 目标

- 为客户、联系人和新增报价表单补齐统一的退出保护。
- 在这三类表单中使用当前值与初始基线比较，恢复原值后不再误提示。
- 保持保存、校验、路由、数据库和业务规则不变。

## 交互规则

1. 新建页的默认值、路由预填值和编辑页异步加载值属于初始基线，不算用户修改。
2. 文本、客户阶段、客户等级或联系人“决策人”发生实际变化后，导航栏返回和 Android 系统返回显示“放弃未保存的修改？”弹窗。
3. 选择“继续编辑”保留输入；选择“放弃修改”退出当前页面。
4. 用户把所有字段恢复为进入页面时的值后，返回直接退出，不显示确认。
5. 保存成功后直接执行既有后续流程，不重复显示退出确认；保存失败继续保持保护。
6. 展开或收起“更多信息”等纯展示状态不属于数据修改。

## 不在本期

- 不改变客户、联系人或报价的字段、校验规则、服务 API 和数据库结构。
- 不迁移其他已接入保护页面的 dirty 判定方式。
- 不实现自动草稿。
- 不调整客户/联系人导入功能入口。
- 不包含 OnePlus/ColorOS 真机验证。

## 验收标准

1. 客户、联系人和新增报价修改后返回均受到保护。
2. 编辑页异步加载及新增页默认/预填值不会误触发保护。
3. 文本与非文本字段恢复初始值后可直接退出。
4. 保存成功不会被保护拦截，保存失败仍保留输入和保护。
5. 聚焦 UT、全量 UT、静态分析、release APK 构建和 Android 模拟器安装启动验证通过。
6. 仓库说明书与应用内使用说明同步。
