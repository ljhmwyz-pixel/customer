# App 与 PRD 匹配度及竞品差异审计

审计日期：2026-08-07  
需求基线：`docs/PRD.md` v2.0（2026-08-05）  
审计对象：当前 Flutter Android 应用、Drift 数据模型、业务服务、路由、自动化测试及既有验收记录

## 1. 执行摘要

当前产品已经形成可用的“客户 -> 多项目 -> 跟进 -> 业务记录 -> 导出/备份”本地 CRM 主链路，客户、项目、日常跟进、筛选、附件、示例数据、四表导出和备份等主体能力已经落地。

按 PRD 第 17 节 16 条验收标准逐条计分：

- 通过：10 条
- 部分通过：4 条
- 未通过：2 条
- 折算匹配度：`(10 + 4 x 0.5) / 16 = 75%`

如果只看客户、项目和日常跟进主链路，完成度约为 85%；若看完整字段、自动业务规则、管理看板和目标真机发布门槛，则不应高于 75%。

最重要的结论不是“还缺多少页面”，而是以下四个端到端断点：

1. `BusinessTaskRules` 已实现并有测试，但生产代码没有调用点。新增报价、样品、注册、招标或订单后，不会自动生成 PRD 规定的节点任务。
2. 看板直接汇总不同币种的最小货币单位，且以原始整数展示，金额结论在多币种数据下不可用于管理决策。
3. 客户、联系人和跟进记录缺少一批 PRD 明确字段，尤其是联系人邮箱/WhatsApp/沟通偏好，以及跟进联系人、客户态度和负责人快照。
4. 一加 13 / ColorOS 15 的连续提醒可靠性仍未验收；PRD 要求连续 7 天，现有验收文档仍写连续 3 天，验收口径本身也需要统一。

## 2. 审计口径

- **通过**：数据、服务、页面入口和自动化证据形成可到达的闭环。
- **部分通过**：主体能力存在，但字段、页面、自动联动、下钻或真机证据不完整。
- **未通过**：PRD 要求的用户结果无法由当前生产流程实现，或发布硬门槛尚未执行。
- 本报告以代码可达性为准，不以计划文档中的“已完成”勾选代替生产链路证据。

## 4. 数据字段完整性

### 4.1 完整度较高

- **项目**：产品、设备、预测、供应商、替代策略、阶段、阻碍和下一步字段基本齐全。
- **报价/样品/注册/招标/订单/任务**：数据库模型覆盖 PRD 的主要业务字段。
- **附件**：跟进、订单、报价、样品、注册和招标均可关联持久化附件。

### 4.2 明确缺失

| 实体 | PRD 字段 | 当前缺口 |
|---|---|---|
| 客户 | 客户编号、客户类型、负责人 | 未落库；负责人只存在于项目和任务。 |
| 客户 | 政府招投标经验、投标资格、投标主体、当地团队、资金能力 | 主要只在具体招标记录中存在，不能形成客户级能力画像。 |
| 联系人 | 邮箱、WhatsApp、沟通偏好、备注 | 未落库；现有字段只有姓名、职位、电话和决策人。 |
| 跟进 | 联系人、客户态度、负责人 | 未落库；无法回答“本次与谁沟通、态度如何、当时谁负责”。 |
| 跟进 | 沟通方式“下拉或简短填写” | 当前为枚举方式，扩展性低于 PRD 描述。 |

这些字段不阻断新增客户和写跟进，但会削弱交接、复盘、联系人分层和招标资格判断，建议在自动任务闭环之后作为下一次数据库迁移统一补齐。

## 5. 关键实现风险

### P0：自动任务未接入生产保存链路

`lib/services/business_task_rules.dart` 已实现报价 2 个工作日/7/14/30/60 天、有效期，样品寄出/签收/测试，注册节点，招标 30/14/7/3/1 天和复购前 30 天规则，也通过 `sourceType + sourceId + ruleKey` 去重。

但目前创建业务记录的服务只调用 DAO 写入，未调用 `generateForOpportunity`。这会造成“规则测试全绿、真实用户没有任务”的高风险假完成状态。

建议修复方式：

1. 在统一业务服务层中完成“保存记录 -> 生成/刷新规则任务 -> 排程提醒”。
2. 数据保存成功但提醒排程失败时保留任务，并显示可恢复警告。
3. 更新业务节点时取消不再适用的未来任务，并补充新的任务；不能只处理首次创建。
4. 增加从页面保存到首页出现任务的端到端测试，而不只测试规则类。

### P0：多币种看板金额口径错误

`dashboardMetrics` 对所有项目的 `forecast_amount_minor` 和所有订单的 `amount_cents` 直接求和，没有按币种分组或换算；页面随后直接显示整数并注明“最小货币单位”。例如 USD 100.00 与 JPY 100 会被当成两个同量级整数相加。

建议短期按币种分组展示，不做隐式汇率换算；未来若确需统一币种，必须保存汇率来源、日期和换算币种。金额指标还应补下钻列表。

### P1：业务记录生命周期不一致

- 订单有新增和编辑路由。
- 报价和样品只有新增入口，无法在 UI 中推进收到反馈、签收、测试等节点。
- 注册和招标服务具备更新能力，但路由没有编辑入口。

这会让“完整表结构”无法转化成持续维护的业务历史。建议为四类对象补统一的详情/编辑/节点推进入口，并保留变更时间线。

### P1：看板不完整

- `stalledQuoteCount` 与 `stalledSampleCount` 当前为 `null`。
- 异常入口只展示长期沉默、内部支持、注册、招标和复购，缺少报价停滞、报价到期、样品停滞等 PRD 类别。
- 未来三个月预计和加权预计没有下钻路由。

### P1：验收口径冲突

PRD 第 16.1 节要求在一加 13 / ColorOS 15 上连续 7 天、触发率 100%、误差不超过 60 秒；`VERIFICATION-2B.md` 仍以连续 3 天为通过条件。发布前必须以 PRD 的 7 天为准，或正式修订 PRD，不能用较短记录替代。

## 6. 竞品差异

竞品分成两组：外贸垂直 CRM（OKKI CRM、孚盟）用于比较外贸获客与业务协同；通用销售 CRM（Zoho CRM、Pipedrive、HubSpot）用于比较自动化、集成和分析平台能力。官网信息核验日期为 2026-08-07。

| 能力 | 当前 App | OKKI / 孚盟 | Zoho / Pipedrive / HubSpot |
|---|---|---|---|
| 产品定位 | 单人、本地、医疗器械外贸执行助手 | 外贸企业获客、客户资产、沟通、团队和订单全流程 | 通用云 CRM 与销售/营销平台 |
| 离线与数据控制 | **强**：SQLite 本机、无账号、断网可用、可完整备份 | 以在线 SaaS 和企业协作为主 | 以云端、移动端和多应用集成为主 |
| 医疗器械业务深度 | **强**：注册、招标资质、授权、替代供应商、样品测试 | 外贸流程强，但官网未显示同等医疗器械专用模型 | 依赖自定义字段、模块和流程搭建 |
| 获客 | 无 | **强**：买家数据、背调、多渠道开发、营销 | 表单、营销、线索获取、第三方集成较强 |
| 沟通渠道 | 记录结果，不连接外部渠道 | **强**：WhatsApp、邮件、社媒、EDM 等统一触达 | 邮件、共享收件箱、电话及大量集成 |
| 自动化 | 规则算法丰富，但生产链路未接通 | 营销、跟进、客户盘活和流程自动化 | **成熟**：工作流、Cadence/Blueprint、活动自动化 |
| 团队管理 | 明确不做多人权限 | 公海、分配、质检、绩效、离职交接 | 权限、管道、活动、报表与团队协作 |
| 分析与 AI | 轻量看板，无 AI | AI 背调、画像、沟通质检、客户盘活、经营分析 | AI 助手、预测、报告、邮件生成和客户洞察 |
| 订单后端 | 订单节点、附件、复购日期 | 孚盟进一步覆盖采购、出口、收款与财务 | 通常依赖内置商务能力或 ERP/财务集成 |
| 实施成本 | **低**：专用字段开箱即用，无订阅与迁移成本 | 采购、配置、培训和持续订阅 | 配置自由度高，但需要实施和持续治理 |

### 6.1 当前 App 的真实优势

1. **业务模型更贴近医疗器械海外销售**：竞品通常需要定制才能同时表达注册、招标、授权、供应商替代和样品测试。
2. **本地可靠与隐私边界清晰**：无网络和账号依赖，适合单人、小规模、敏感客户资料场景。
3. **执行负担低**：五字段跟进、今日任务和预设业务规则比通用 CRM 的配置成本更低。
4. **数据可迁移**：四表 Excel 与完整 ZIP 备份比封闭式 SaaS 更利于自主管理。

### 6.2 当前 App 的结构性劣势

1. 没有邮件、WhatsApp、社媒和网站线索自动采集，沟通内容依赖手工记录。
2. 没有团队分配、公海、权限、审批、绩效和离职交接，不适合多人规模化运营。
3. 没有营销自动化、客户背调、AI 画像或自动沟通摘要。
4. 没有采购、出口单证、收款核销和财务闭环，不能替代外贸 ERP。
5. 自定义模块、字段、工作流和第三方集成能力远弱于通用 CRM 平台。

### 6.3 定位建议

当前产品不应在下一阶段追赶“大而全”的 SaaS CRM。更合理的定位是：

> 面向单人或极小团队的、离线优先的医疗器械外贸项目推进与提醒助手。

先把自动规则、业务节点更新、字段完整性、看板口径和真机提醒做成可信闭环。只有当真实用户出现多人分配、跨设备同步或沟通自动归档需求时，再单独评估云同步与团队版，避免破坏当前低成本、低录入负担和本地隐私优势。

## 7. 建议排期

### P0：发布前必须完成

1. 将 `BusinessTaskRules` 接入报价、样品、注册、招标、订单的新增与更新流程。
2. 补端到端测试：保存业务节点后，任务去重生成、提醒排程、首页可见。
3. 修正看板多币种汇总与金额展示，至少按币种分组。
4. 统一 7 天真机验收口径，并完成一加 13 / ColorOS 15 记录。

### P1：下一个业务版本

1. 为报价、样品、注册和招标补详情、编辑和节点推进入口。
2. 补客户、联系人和跟进缺失字段及数据库迁移。
3. 补齐看板报价/样品异常、停滞计数和全部统计下钻。
4. 完成生产类备份的破坏性恢复演练及目标机文件提供器验证。

### P2：有真实需求再做

1. 邮件/WhatsApp 的半自动归档或分享导入，不直接扩成完整营销平台。
2. 可选的加密跨设备备份或只读 Web 报表。
3. AI 摘要、跟进建议和客户画像，但不得代替业务员做报价、授权或投入决策。
